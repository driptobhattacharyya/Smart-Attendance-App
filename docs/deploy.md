# Attendify: deployment runbook

Do the steps in order. Each step says what you get and what to write down. Total time for a first deploy: about 2 hours.

```
phone app / browser
      |  https://smartattendance.driptobhattacharyya.com
      v
Cloudflare Pages  (admin SPA, /download, and the /api proxy Function)
      |  /api/*  + header X-Origin-Auth
      v
AWS Lambda Function URL (ap-south-1, container image, FastAPI)
      |
      v
PostgreSQL (Supabase / Neon / RDS, via a transaction pooler)
```

Detail pages: `infra/aws/README.md`, `infra/cloudflare/README.md`. Tools you need locally: `git`, Docker, `uv`, Node 22, AWS CLI, AWS SAM CLI, and accounts on AWS, Cloudflare, a managed PostgreSQL provider, GitHub and Expo (expo.dev).

## 0. PostgreSQL (backend v5, replaces the MongoDB steps below)

The v5 backend (`docs/architecture-v5.md`) uses PostgreSQL 16 only. Sections 1 and 5 below describe
the old MongoDB setup and are superseded by this section; the rest of the runbook still applies.

1. Create a Postgres 16 database (Supabase, Neon or RDS). From Lambda use the provider's
   **transaction-mode pooler** endpoint (Supabase pooler port 6543, Neon pooled host, RDS Proxy).
   The app already disables asyncpg's prepared statement cache (`statement_cache_size=0`) and only
   sets tenant context with `SET LOCAL` inside a transaction, which is what transaction poolers
   require. Set `DB_NULL_POOL=true` for Lambda (the template does) so the app keeps no pool of its own.
2. Run migrations as the **owner** role over a **direct** (non-pooled) connection, from your machine
   or CI:

   ```bash
   cd backend
   export DATABASE_OWNER_URL='postgresql://postgres:OWNER_PASSWORD@db-host:5432/postgres'
   export ATTENDIFY_APP_PASSWORD='<random>' ATTENDIFY_SYSTEM_PASSWORD='<random>'
   uv run alembic upgrade head
   ```

   The first migration creates the two login roles if they do not exist and, when the two password
   variables are set, sets their passwords. It also creates every table, the row level security
   policies (`FORCE ROW LEVEL SECURITY`) and all grants.
3. The two roles. `attendify_app` serves requests: not the table owner, no `BYPASSRLS`, every
   transaction starts with `SET LOCAL app.org_id`. `attendify_system` has `BYPASSRLS` and is used only
   by org signup, pre-login auth lookups (login, refresh, reset, invite) and desk device-token calls.
   If your provider does not let the migration user create a `BYPASSRLS` role (Supabase: use the
   dashboard SQL editor as `postgres`), create them first and re-run the migration:

   ```sql
   CREATE ROLE attendify_app LOGIN PASSWORD '...' NOBYPASSRLS;
   CREATE ROLE attendify_system LOGIN PASSWORD '...' BYPASSRLS;
   ```

   Supabase pooler user names look like `attendify_app.<project-ref>`; put that in the URL.
4. Lambda environment (the SAM template parameters): `DATABASE_URL` (app role, pooler),
   `DATABASE_SYSTEM_URL` (system role, pooler), `DATA_KEY` (base64 of 32 random bytes; encrypts device
   secrets, losing it means re-pairing all desk apps), `JWT_SECRET`, `INTERNAL_JOB_SECRET`.
5. Seed demo data (optional, never in production): `uv run python -m scripts.seed` with the same
   `DATABASE_URL` / `DATABASE_SYSTEM_URL`. Real customers sign up with `POST /api/v1/orgs/signup`.
6. Backups: use the provider's point-in-time recovery; the database is the only state.

## 1. MongoDB Atlas (superseded, see section 0)

1. Create an Atlas project and a cluster. Start with **M0 (free)** on AWS `ap-south-1` (Mumbai); upgrade to M10 later (see costs).
2. Database Access, Add New Database User: username `attendify_app`, authentication "Password", click Autogenerate Secure Password and copy it. Built-in role: **Only read and write to a specific database** with database `attendify`. Do not give it Atlas admin.
3. Network Access, Add IP Address, `0.0.0.0/0` (Lambda has no fixed IP; see `infra/aws/README.md` for the paid alternatives).
4. Connect, Drivers, copy the `mongodb+srv://...` string and put the real password in (URL-encode special characters; autogenerated passwords are safe). Append the DB name if you like: `mongodb+srv://attendify_app:PASSWORD@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority`.

Write down: **MONGODB_URI**.

## 2. Generate secrets

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"   # run twice
```

First output is **JWT_SECRET**, second is **ORIGIN_SECRET**. Keep them in a password manager. Changing JWT_SECRET logs everyone out; ORIGIN_SECRET must be identical in AWS and Cloudflare.

## 3. Deploy the API to AWS

```bash
aws configure sso            # or: aws configure   (admin-level profile for this first deploy)
cd infra/aws
sam build
sam deploy --guided          # stack attendify-api, region ap-south-1, paste the 3 secrets
```

Answers to the prompts are listed in `infra/aws/README.md`. When it finishes, copy the `FunctionUrl` output (looks like `https://abcd1234.lambda-url.ap-south-1.on.aws/`).

Check it:

```bash
URL=https://abcd1234.lambda-url.ap-south-1.on.aws
curl -s $URL/api/health                       # {"status":"ok","face_recognition":true}
curl -s -o /dev/null -w "%{http_code}\n" $URL/api/auth/me     # 403 (no secret: working as intended)
```

`"face_recognition": true` confirms the OpenCV models were baked into the image. The first call after idle can take several seconds (cold start).

Write down: **API_ORIGIN** (the Function URL).

## 4. Cloudflare Pages and DNS

Full detail in `infra/cloudflare/README.md`. Short version:

```bash
cd admin
npm ci && VITE_API_URL=/api npm run build
npx wrangler login
npx wrangler pages project create smartattendance --production-branch main
npx wrangler pages secret put API_ORIGIN    --project-name smartattendance   # step 3 URL
npx wrangler pages secret put ORIGIN_SECRET --project-name smartattendance   # step 2 value
npx wrangler pages deploy dist --project-name smartattendance --branch main
```

Then in the Cloudflare dashboard: Workers & Pages, `smartattendance`, Custom domains, add `smartattendance.driptobhattacharyya.com` and accept the DNS record. Wait for Active.

```bash
curl -s https://smartattendance.driptobhattacharyya.com/api/health
```

must return the same JSON as step 3. This proves Cloudflare, the secret and Lambda are all wired.

## 5. Create the first admin and office

Run the seed script from your machine against the Atlas database (it needs the connection string only; it prints the generated passwords once):

```bash
cd backend
uv sync
MONGODB_URI='mongodb+srv://...' MONGODB_DB=attendify JWT_SECRET='<JWT_SECRET>' ENVIRONMENT=production \
  uv run python -m scripts.seed --lat <office latitude> --lon <office longitude> --tz Asia/Kolkata
```

It creates one office, an admin, a manager and an employee. Save the printed passwords, sign in to the admin panel at `https://smartattendance.driptobhattacharyya.com/`, change the demo accounts' passwords, and delete the demo manager/employee if you do not want them. (Add `--help` to see options such as the office name and radius.) Consider turning off public sign-up once your staff are registered by setting `AllowSelfRegistration` to `false` in the stack.

## 6. Turn on continuous deployment (GitHub)

1. Create the AWS OIDC deploy role as described in `infra/aws/README.md` ("Continuous deployment").
2. GitHub repo, Settings, Secrets and variables, Actions:
   - Variable: `AWS_DEPLOY_ROLE_ARN`
   - Secrets: `MONGODB_URI`, `JWT_SECRET`, `ORIGIN_SECRET`, `CLOUDFLARE_API_TOKEN` (Cloudflare, My Profile, API Tokens, template "Edit Cloudflare Workers" or a custom token with Account, Cloudflare Pages, Edit), `CLOUDFLARE_ACCOUNT_ID` (shown in the dashboard sidebar of Workers & Pages), `EXPO_TOKEN` (expo.dev, Account settings, Access tokens)
3. Pushing to `main` now runs `ci.yml`, and `deploy-backend.yml` / `deploy-admin.yml` when `backend/`+`infra/aws/` or `admin/` changed.

## 7. Build and publish the Android app (EAS)

One time:

```bash
cd mobile
npm ci
npx eas-cli login
npx eas-cli init               # links the project to your Expo account (updates app.json with a project id; commit it)
npx eas-cli env:create --name GOOGLE_MAPS_API_KEY --value '<your Google Maps key>' --visibility secret --environment preview --environment production
```

(The Maps key is read by `app.config.js` at build time. Without it, map views in the app will be blank.)

Build an installable APK (`preview` profile, `buildType: apk`, API URL already set in `eas.json`):

```bash
npx eas-cli build --platform android --profile preview
```

or run the GitHub workflow "Mobile build (EAS)" from the Actions tab. When it finishes, the log shows the build page and an artifact `.apk` URL.

Publish the download link:

1. Download the APK from the EAS build page. (EAS artifact links expire, so do not link to them directly.)
2. Create a GitHub Release (for example `v1.0.0`) and attach the APK. Copy the asset's URL (private repos: make a public release repo, or host the file on Cloudflare R2/any static host instead).
3. Edit `admin/public/download/latest.json`:

   ```json
   { "version": "1.0.0", "url": "https://github.com/<owner>/<repo>/releases/download/v1.0.0/attendify.apk", "updated": "2026-11-07" }
   ```

4. Commit and push to `main` (the admin workflow redeploys). Share `https://smartattendance.driptobhattacharyya.com/download` with staff. They must allow "install unknown apps" for their browser once.

iOS: needs the Apple Developer Program ($99/year). Then `npx eas-cli build --platform ios --profile production` and `npx eas-cli submit --platform ios` to TestFlight. Play Store (optional): `--platform android --profile production` produces an AAB; `eas submit --platform android` uploads it (Google Play developer account, one-time $25).

## 8. Smoke tests

Replace `D=https://smartattendance.driptobhattacharyya.com`.

```bash
D=https://smartattendance.driptobhattacharyya.com

curl -s  $D/api/health                                   # status ok, face_recognition true
curl -s -o /dev/null -w "%{http_code}\n" $D/             # 200 admin SPA
curl -s -o /dev/null -w "%{http_code}\n" $D/some/route   # 200 (SPA fallback)
curl -s -o /dev/null -w "%{http_code}\n" $D/download/    # 200 download page
curl -s -o /dev/null -w "%{http_code}\n" $D/api/auth/me  # 401 (reached the API, needs a token)

# bypass check: the raw Lambda URL must refuse requests without the secret
curl -s -o /dev/null -w "%{http_code}\n" https://abcd1234.lambda-url.ap-south-1.on.aws/api/auth/me   # 403

# login (use the admin password printed by the seed script)
curl -s -X POST $D/api/auth/login -H 'content-type: application/json' \
  -d '{"employee_id":"<admin email or EMP id from the seed output>","password":"<password>"}'
```

A JSON body containing a token means login works. Finally, install the APK on a phone, sign in, and run a check-in at the office location.

## 9. Operations

- Logs: CloudWatch log group `/aws/lambda/attendify-api-api` (30 days retention).
- Uptime: point a free monitor (UptimeRobot) at `$D/api/health` every 5 minutes; this also keeps a Lambda container warm during the day.
- Rotate a secret: update the GitHub secret and re-run `deploy-backend` (for `ORIGIN_SECRET` also update the Cloudflare secret and redeploy the admin, ideally within the same minute).
- Roll back: `git revert` and push, or in the Lambda console point to a previous image via redeploying an older commit.
- Backups: Atlas M0 has no backups. Use `mongodump` on a schedule, or upgrade to M10 (continuous backup).

## 10. Monthly cost estimate (small company, about 50 employees)

Prices are USD, from memory of public price lists, and **approximate**; check the pricing pages before committing. Assumes about 600k API requests/month (check-in plus a heartbeat per employee about every minute while at work), 150 ms average, 1 GB arm64.

| Item | Estimate | Notes |
|---|---|---|
| AWS Lambda | about $0 | ~90k GB-seconds and 0.6M requests/month, inside the always-free tier (400k GB-s, 1M requests). Beyond it: about $0.0000133/GB-s (arm64, approximate) + $0.20 per 1M requests. 200 employees would cost roughly $1 to $3. |
| Lambda Function URL | $0 | no extra charge |
| ECR image storage | about $0.10 to $0.50 | ~1 GB at about $0.10/GB-month; keep few images |
| CloudWatch Logs | about $0.50 to $2 | $0.50/GB ingested (approximate); first 5 GB/month free for ingestion in most regions. Set log level modestly. |
| Data transfer out (AWS) | about $0 to $1 | 100 GB/month free aggregate; responses are small JSON |
| MongoDB Atlas **M0** | $0 | 512 MB storage, shared CPU, no backups, rate limited; face embeddings are small (128 floats per user) so 50 to a few hundred employees fits comfortably, but expect slower cold performance |
| MongoDB Atlas **M10** | about $57 to $60 | roughly $0.08/hour (approximate; varies by region), 10 GB, backups, dedicated. Upgrade when you need backups or SLAs. |
| Cloudflare Pages + Functions + DNS + SSL | $0 | free plan; 100k function requests/day is plenty here |
| Domain | about $10 to $12 per year | already owned; `.com` renewals, approximate |
| EAS (Expo) | $0 | free tier has a limited monthly build allowance (about 30 builds, iOS fewer, lower priority queue; approximate). Paid starts around $19/month if you need more. |
| Apple Developer Program | $99 per year (about $8.25/month) | only if you ship iOS |
| Google Play developer account | $25 one time | only if you publish on Play Store; direct APK download needs nothing |

Totals per month:

- **Lean (Atlas M0, Android APK via download page):** about **$1 to $3**.
- **Lean + iOS:** about $9 to $11 (Apple's $99/year spread monthly).
- **Production-grade (Atlas M10, iOS + Play):** about **$65 to $75** (M10 dominates), plus the one-time $25.
- Optional extras: provisioned concurrency to remove cold starts about $10; NAT gateway with fixed IP for Atlas about $35 or more; Cloudflare Workers paid plan $5.
